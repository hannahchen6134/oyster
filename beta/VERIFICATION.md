# 上線前驗收表（喵喵照護安心管家）

對外開放前，照這份一條條驗。分三級：
- 🔴 **P0**：壞掉會砸招牌或洩漏隱私，**必須真機/真人測過才敢對外**。
- 🟡 **P1**：記錄正確性，跑一遍冒煙測試就守住（見 `CHECKLIST.md`）。
- 🟢 **P2**：規模化才會痛，5 人測試階段先不用做，但要知道它存在。

「程式已確認」= 我已從程式碼稽核過把關邏輯；「需真機/真人」= 非得實際裝置或兩個帳號才能驗。

---

## 🔴 P0 — 一定要驗證

- [ ] **1. iOS 存圖不空白**（需真 iPhone）
  - 用 iPhone 開照護站 → 回顧 → 存成圖片 → 確認**不是白圖**、能長按存到相簿。
  - 已修：只有 iOS 才「暖身算一次」避免首算空白。開發環境無 iOS，這條只能你/測試者測。

- [ ] **2. 資料隔離**（程式已確認 ✓，仍需真人交叉測）
  - 每個資料端點都有 `assertPetOwner`/`ownerColumn` 把關；共同照護者寫入以「飼主本人」解析、只能碰自己連結的飼主的貓。
  - 真人測：A 的帳號看不到/改不到 B 的貓；未開通（betaAccess=0）者看不到任何內容。

- [ ] **3. 報告圖內容正確**（需真人）
  - 多貓帳號下，產生的圖 = 當下這隻貓、日期區間正確、內容沒被截掉。

- [ ] **4. /shot 隱私取捨**（程式已確認 ✓）
  - 報告圖（含健康資料）存伺服器、用長亂數網址取，noindex、每晚清、解碼有防護。
  - 屬「能力憑證」模式（有網址就能看）——beta 可接受，你要知道這個取捨。

## 🟡 P1 — 該測（記錄正確性）

- [ ] **5. 加水正確**：LINE「罐頭 30 水 10」記成單筆、今天喝水 +10；網站食物編輯改加水有連動。
- [ ] **6. 多筆解析**：「水20 乾糧4 藥早已吃」= 三筆、當日總量正確。
- [ ] **7. 不重複回覆**：同一則指令不會收到兩次回覆（持久去重已修）。
- [ ] **8. 每晚提醒**：晚上 9 點真的推、且變成手機通知（別把管家靜音）。
- [ ] **9. 新用戶/空狀態**：沒貓沒食物時每頁不崩、有引導。
- [ ] **10. 連結過期**：30 天過期 → 優雅提示回 LINE 拿新連結，不是白畫面（程式已確認 401→回登入 ✓）。
- [ ] **11. 熱量誠實**：沒設公式顯示「估算」不假準；設公式後歷史自動補算。
- [ ] **12. 藥時段**：LINE 記「藥 已吃」依記錄時間自動歸早/晚；今日卡藥只顯示一次。
- [ ] **13. 切貓**：切到另一隻後，記錄記對貓；確認訊息有教「怎麼切回去」。

## 🟢 P2 — 監看／之後優化

- [ ] **LINE 推播額度**：免費方案每月上限（約 200–500 則）；每晚提醒 × 人數會吃額度，規模大注意成本。
- [ ] **錯誤可觀測性**：目前無自動告警；beta 用 `wrangler tail`；使用者收到「系統忙碌中」= 有 throw 要追。
- [ ] **首次載入**：單一大 HTML（~260KB），慢速手機略久，beta 可接受。
- [ ] **CI**：`npm test` 目前靠自律；之後可設成強制 pre-deploy。
- [ ] **D1 成長**：report_shots、訊息去重都有每晚 cron 清，確認有清。
