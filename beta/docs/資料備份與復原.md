# 資料備份與復原方案

「客戶資料不能不見」的四層保險，由內而外：

## 第 1 層｜軟刪除（隨時生效，零設定）
使用者按「刪除」只是把資料標記為已刪除（isDeleted=1），資料仍在資料庫裡。
誤刪可以直接把該筆標記改回來，不會真的消失。

## 第 2 層｜Cloudflare D1 時光機（自動，零設定）
Cloudflare 自動保存資料庫「過去每一分鐘」的狀態（免費方案至少 7 天）。
不管是誤操作還是程式出錯，都可以整庫回到任一時間點：

```bash
# 看目前的還原點
npx wrangler d1 time-travel info cat-care-beta

# 回到指定時間（UTC）
npx wrangler d1 time-travel restore cat-care-beta --timestamp="2026-07-10T12:00:00Z"
```

## 第 3 層｜每日自動異地備份（需一次性設定，約 3 分鐘）
每天台北時間 02:00，自動把整個資料庫匯出成 SQL 檔，存到 GitHub 私有倉庫（60 天輪替）。

一次性設定步驟：
1. 到 https://github.com/new 建立倉庫，名稱 `oyster-backups`，
   **Visibility 務必選 Private**，勾 Add a README
2. 把本目錄 `ops/backup-workflow.yml` 的內容放到該倉庫的
   `.github/workflows/backup.yml`
3. 該倉庫 Settings → Secrets and variables → Actions → New repository secret，
   新增兩個：
   - `CLOUDFLARE_API_TOKEN`（Cloudflare API Token）
   - `CLOUDFLARE_ACCOUNT_ID`（帳號 ID）
4. 到 Actions 分頁手動 Run 一次「每日資料庫備份」確認成功

之後每天自動備份，SQL 檔在該倉庫的 `backups/` 資料夾，任何一天的檔案
都可以用 `wrangler d1 execute cat-care-beta --remote --file=備份.sql` 還原。

## 第 4 層｜重大變更前手動快照（開發慣例）
每次資料表 migration 或大量資料操作（如舊站匯入）前，先執行
`wrangler d1 export` 留存快照再動手，並保留回滾方案。

## 平時可以做的
- 每隔一段時間跟 Claude 說「幫我做一份完整備份」，把 SQL 檔自己存一份
- 主程式倉庫（oyster）目前是公開的：程式碼公開沒問題，但備份與任何
  客戶資料絕對不能放進去；若不想公開程式碼，到 oyster 倉庫
  Settings → General → Danger Zone → Change visibility 改成 Private
